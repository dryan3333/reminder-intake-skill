# 产品评审

## 产品定位
帮助用户在讨论结束或切换任务时，把明确的下一步交给可信的提醒系统。核心价值是减少记忆负担，并保留“为什么要做”的简短上下文。

第一版服务频繁切换任务、使用AI处理实际交付的人。完成标准不是创建更多提醒，而是用户能在合适时间收到可执行的下一步。

## 主要问题与设计取舍
| 问题 | 设计 |
|---|---|
| 看到日期就打断 | 只处理用户自己的可执行事项；模糊愿望与历史日期不触发 |
| 每次都选平台 | 已确认偏好复用；首用才选择，无法知道偏好时明确询问 |
| 半途停聊被误判 | 沉默不等于暂停授权；收尾或恢复时一次性提议 |
| 日历太拥挤 | 固定预约入日历，行动项优先提醒事项，均尊重用户选择 |
| 相对日期算错 | 按源消息日期与时区解释；旧记录不套用今天 |
| AI声称设好了却没通知 | 区分候选/已创建/待导入；回读记录及通知字段 |
| Codex与Claude各建一遍 | 目标平台ID作为去重基准；缺共享状态不承诺跨AI去重 |
| 将私人聊天公开 | 简短中性标题、最少描述；接力索引与聊天数据不入公开仓库 |
| 不同AI工具不同 | 共享语义规则，工具由宿主决定；无写入能力提供草稿 |

## 第一版与后续
第一版包含：识别、合并候选、确认预览、按现有工具创建/更新、结果核对、减少重复。默认不监听所有窗口，不自动安装连接器，不承诺关闭电脑后的后台执行。

后续应优先做：稳定的日历/任务适配器、可撤销动作、用户可控的私人接力账本。后台跨聊天扫描应作为独立产品能力，明确范围、触发时间和退出方式，不伪装成技能自带功能。

## 评估指标
用虚构或授权样本评估：误触发比例、每个事项需要追问次数、错误日期次数、重复创建次数、创建回读成功率、用户拒绝后再次催问次数。未进行真实用户研究前不宣称改善百分比或市场需求已验证。

## 本次协作评审
Claude CLI审查5项，两个独立agent分别审查体验与可靠性。合并修改包括：稍后决定和停止主动提议、源时区与夏令时、单次/整组修改、单一写入者与版本冲突、待核验状态、过期任务、放弃与暂停、失败降级。未采纳仅凭主题/日期相同就认定同记录的建议，改为优先记录ID，候选不唯一时用户选择。保留真实写入与通知验证未完成的限制。

## 用户实测修正：决策过多
用户接受“加入”后，助手又询问年份、平台、开始时间和提前量，造成过多决策。改为先展示一个推荐方案，用户只决定加入或调整；平台一次配置后复用，未知开始时间的明确日期日程可以提议全天。仅保留实际阻碍创建或可能写错日期的澄清，未授权推荐值仍不能当已确认。

## 选择交互
优先宿主原生选项弹窗，推荐方案、调整、暂不加入，不让用户输入多字段。预选不是授权；无结构化提问能力的环境使用短编号选项。
