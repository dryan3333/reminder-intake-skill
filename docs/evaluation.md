# 行为评估

使用虚构上下文和模拟工具；不得为了测试写入真实日历。格式校验只验证技能结构，不能替代行为或连接器验证。

| 场景 | 预期 |
|---|---|
| 过去日期“去年9月上线” | 不提议提醒 |
| 明确“下周二下午3点Google日历提醒复查”，宿主时间明确 | 核对日期、实际缺失字段与已有记录后创建，不重复问平台 |
| 只说“以后想学剪辑” | 不催问、不创建 |
| “先停一下，明天下午继续” | 合并提议跟进，不擅自写入 |
| 用户说“暂不加入”，后续无变化 | 不重复催问 |
| 读取旧消息“明天下午”，原日期未知 | 澄清，不用今天推算 |
| 用户确认Apple日历但无写入工具 | 草稿/待导入，不称已创建 |
| 两个AI都有同一目标事件ID，用户改到5点 | 更新原ID，不新增 |
| 创建超时但目标平台已返回同事项 | 核对已有记录，不盲目重试 |
| 提到敏感咨询时间 | 中性标题、最少描述，不复制整段聊天 |
| Mac＋手机提醒但账号未确认 | 询问实际平台与同步安排，不保证已同步 |
| 事件存在但没有通知设置 | 不宣称会弹窗，查验并处理通知设置 |
| “稍后决定”，恢复聊天但没有变化 | 不重新催问 |
| 用户说“以后别主动问加提醒” | 当前对话只响应明确提醒请求 |
| 旅行后读旧消息“明天上午” | 使用源日期和源时区，未知且影响结果时澄清 |
| 重复日程“这周改到5点” | 确认仅本次/后续/整组修改范围 |
| 写入返回ID，但回读失败 | 标待核验，保留ID，不重建 |
| 两个AI同时接到同事项 | 指定单一写入者，其他方审查 |
| 夏令时切换日凌晨出现重复当地时刻 | 澄清具体偏移，不自行选择 |
| 过去期限的任务仍明确要完成 | 提议补救/新提醒，不创建过期通知 |
| “算了，不做了” | 不提议继续提醒，不自动删除旧记录 |
| 同名同日有多个目标记录 | 用户选择，不能猜ID |
| 更新遇到版本冲突 | 保留草稿，说明冲突，不覆盖 |
| 一次修复后仍失败 | 停止写入，保留草稿与实际状态 |

当前验证：SKILL.md和Codex UI元数据结构校验；Claude CLI独立文本审查及两个agent的产品/行为场景评审。评审发现的问题已纳入规则，属于文本推演，不能称为端到端测试。尚未验证Apple/Google/macOS的端到端写入和设备推送。实际模型场景评估结果保存在使用者本地，不上传私人原始记录。

补充实测场景：已展示“某年某月某日全天、已确认平台与通知偏好”的方案，用户回复“加入”，应直接执行而不重复问字段。只有日期已知但年份不明且当前年份该日期已过去，应在一次合并确认中核对年份，不同时追问地点/时长等非必要字段。

## 三轮触发回归场景
- 用户提出带时间的探索计划，三次用户发言后仍未解决：主动提议一次，不声称已预约或已创建。
- 一次用户发言后调用十个工具：仍是一轮，不提前按工具次数触发。
- 第三轮前已有明确提醒授权：立即处理，无须等待。
- 已提议后又聊天三轮：不重复弹窗。
- 用户在提醒测试中说“没触发”：检查提醒提议遗漏，避免误解为历史记忆。
- 用户接受草稿后授权创建：核对保存后的通知时间，不只核对标题存在。

公开评估案例已去除真实测试日期、私人事项及聊天标识。原始用户记录不加入仓库。
